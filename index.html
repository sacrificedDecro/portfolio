What I've built

Dead rails - drag, weight & throw
Dragging runs on real physics: the server hands the grabbed part's network ownership to your client and holds it with AlignPosition/AlignOrientation, so heavier props genuinely resist being dragged, not just tinted red. Let go mid-swing and a short velocity sample turns it into a real throw, capped so nothing rockets off the map. Footsteps got their own pass too — a looping sound crossfades in and out as you start and stop running, driven by the server so it stays in sync for everyone watching.
Gist
Simple combat system
M1/M2 combos, sprint attacks that hit harder and knock further, and a real block that shrugs off damage — unless you land it from behind, which breaks straight through. Hits land with randomized-pitch sound, blood, and a red flash. Two training dummies spar on their own in the scene, so the whole system is watchable solo.
Gist
R6 & R15 ragdoll system
Works on R6 and R15 without special-casing either rig — it walks every joint in the character and handles whatever it finds, swapping Motor6Ds for BallSocketConstraints and easing off AnimationConstraints, then drops every part into its own collision group so limbs don't fling apart from self-collision. Dying triggers a permanent ragdoll automatically (BreakJointsOnDeath is off, so nothing explodes on its own) — press R any other time for a togglable one, with the camera swapping to follow the head while you're down.
Gist
Inventory slot UI & custom interact prompt
The interact prompt is fully custom, no ProximityPrompt — just a CollectionService tag and an outline Highlight on whatever's nearest. Pickup, equip, and drop each get their own sound cue, and all three only fire after the server confirms the action actually went through. The save system is the real work: each server claims a session lock before loading your inventory, and a heartbeat keeps renewing it, so joining a second server mid-session gets you turned away instead of a duplicated item. Footsteps sync to the walk animation's actual keyframes instead of a fixed timer, so they land exactly when the foot does.
Gist
Tink — game framework
A from-scratch Knit-style service/controller framework, no dependency on the archived original. Every remote gets automatic per-player rate limiting before your handler even runs. Startup is fault-isolated too — if one service throws on init, only that one gets skipped, logged with a full traceback, while everything else boots normally.

Payment

How I work

Pay per task by default. Each commission gets broken into small pieces and you pay for each one as it's delivered. If you'd rather do a simple 50/50 (upfront and on delivery), that works too. No rev-share, no "pay when the game ships." Gift cards and crypto aren't accepted; ask if you have something else in mind.

Ownership

As soon as a task is paid for, that code is fully yours. You can modify it, ship it anywhere, and I don't keep a copy.

Refunds

You can walk away anytime. Per-task means you only pay for what's been delivered; with 50/50, the upfront half is refundable until I've started.

Availability

Available daily from 18:00 to 1:00 (UTC+3). I reply within hours on Discord, slower on email.
